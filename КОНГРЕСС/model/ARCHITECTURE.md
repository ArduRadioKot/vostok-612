# Architecture: ML модель для прогноза размещения атомной станции малой мощности

> Версия: 1.0 | Дата: 2026-10-11 | Цель: **где + какую** станцию ставить на Дальнем Востоке / Арктике с учётом топливного цикла (ЗЯТЦ) и рентабельности.

## 1. Проблема и цель

Задача состоит из двух взаимосвязанных подзадач:

1. **Где?** — выбрать/ранжировать площадку из списка изолированных энергорайонов РФ (ДВ + Арктика).
2. **Какую станцию?** — подобрать тип реактора (из каталога ~29 быстронейтронных и SMR-вариантов), число модулей и оценить окупаемость.

Требуется **несколько согласованных моделей** (не одна чёрная коробка): экономика, экспертный балл, риск, стратегия — с последующим Парето-отбором и обязательным пояснением каждого решения.

---

## 2. Что есть в данных (Слой 0)

Извлечено из файлов проекта в `model/data/`:
- **21 площадка** (`sites.csv`) — оценка по 6 критериям:
  - `deficit`, `oyat` (наличие ОЯТ), `logistics`, `industry`, `economy`, `geo_climate` (1–5 баллов)
  - `expert_score` — простая сумма (внимание: противоречит детальному анализу; Большой камень = 25, но Сахалин лучше по экономике и доступности)
- **26 реакторов** (`reactors.csv`) — характеристики:
  - P_эл, P_теп (МВт), теплоноситель (Na / Pb / PbBi / жидкосолевой), безопасность, срок службы зоны, габариты, мин. площадь, страна
- **Нагрузка**: суточный профиль РДУ Якутии (зима 669–905 МВт, лето ниже).
- **Экономика-якорь**: Южно-Сахалинск CAPEX/OPEX/LCOE/окупаемость из `Южно-Сахалинск вся экономика.xlsx` и `Экономика сравнения…`.
- **Жёсткие правила** из документов: дефицит ≥30 МВт, изоляция от ЕЭС, негабарит ~270 т → железнодорожный паром и морская доставка.

**Пробелы**, которые предстоит восполнить внешним обогащением:
- Координаты площадок
- Точный дефицит (МВт) — сейчас только шкала 1–5
- Цена привозного топлива по локациям
- Уровень сеизмичности (сейчас текстом: Чукотка 7–8, Камчатка 7–8, Сахалин 7–8)
- Наличие пресной воды / морской воды для охлаждения
- Доступность крупногабаритного порта

Для MVP можно заменить недостающие входные данные **прокси из текста документов** (описания логистики, климата, сеизмичности приведены для каждой площадки).

## 4. Выбор алгоритмов и обоснование

### Почему не обычная нейросеть?
- Обучающих примеров ~21 площадка (мало для NN).
- Требуется **объяснимость**: судьи/congress demands reasons.
- Есть **жёсткие физические ограничения** — нельзя передавать нейросети неявно.
- Есть **якорный кейс** (экономика Сахалина) — нужно использовать как anchor.

### Модель ценности площадки `V_expert(s)`
**Gaussian Process (GP)** — идеально для малых выборок: выдаёт предсказание + полоску доверия. Можно задать ядро по полуэмпирическим весам 6 критериев. Результат: ранг площадок с Confidence Interval.
**Альтернатива / дополнение**: `learning-to-rank` LightGBM на `expert_score` → SHAP-веса критериев, удобно для презентации.

### Модель экономики `V_econ(s,r,n)`
**Гибридная**: аналитическое ядро (NPV формула) + LightGBM residual.
Формула параметрически описывает влияние дефицита, цены топлива, CAPEX-множителей, наличия ЗЯТЦ. LightGBM корректирует остаток ошибки при накоплении данных.

### Оптимизатор
Полное перебирание допустимых `(s, r, n)` (~21×26×(1..Nmax) = несколько сотен комбинаций) тривиально.
Далее — **Pareto front** по 4 критериям: NPV, риск, стратегия, экспертный балл.
При масштабировании — перейти к PuLP/OR-tools (целочисленное программирование).

### Monte-Carlo для неопределённости
Параметры с разбросом: дефицит (±20%), цена топлива (±30%), задержка стройки (±2 года).
Вывод: распределение `E[NPV]`, `P(NPV > 0)`, `VaR(95%)`. Ответ вида *«Сахалин лидирует с вероятностью 87% по NPV, но Анадырь ближе к нулю по риску»* вместо плоского рейтинга.

## 5. Прогнозируемый выход модели

1. **Лучшая площадка + лучший реактор + N модулей** — по каждому из 4 критериев (эксперт, эконом, риск, стратегия).
2. **Top-5 рекомендаций** с объяснением (SHAP + ограничения).
3. **Карта** с раскрашиванием по выигрышности.
4. **Устойчивость к сценариям** (что будет, если цена дизеля упадёт/растёт?).
5. «Красные линии»: какие варианты убивает геометрия/логистика/сеизмика.

## 6. Технические детали реализации

**Стек**: Python 3.11+, pandas/polars, numpy, scikit-learn, lightgbm, gpytorch/scikit-gaussian-process, PuLP, shap, folium/plotly, pytest.

**Структура папок (планируется)**:
```
model/
  data/
    sites.csv              ← уже создано (21 запись)
    reactors.csv           ← уже создано (26 записей)
    load_profile_yakutia.csv
  src/
    gate.py                # Слой 1: hard constraints
    models/expert_ranker.py
    models/econ_model.py
    models/risk_model.py
    optimiser.py           # Слой 3
    explanation.py         # SHAP / карты
  output/
    recommendations.json
    pareto_front.png
    site_map.html
```

**Этапы разработки**:
- Phase 0 (готово): данные собраны, архитектура согласована.
- Phase 1: Gate + аналитическая NPV-формула → первый грубый рейтинг.
- Phase 2: GP/LTR + SHAP → объяснимая оценка площадок.
- Phase 3: Monte-Carlo + Pareto → устойчивые рекомендации.
- Phase 4: интерпретация, визуализации, защита.

## 7. Что нужно от вас дальше (inputs / decisions)

1. **Весовой приоритет 4 критериев** (или оставить равным взвешивание в Парето). Можно начать с равных, потом настроить под запрос заказчика.
2. **Внешние данные для обогащения** — есть ли у вас точные дефициты (МВт), координаты, тарифы, температура? Если нет — заполню прокси из текстов документов и явно отмечу как proxy.
3. **Число модулей n** — максимум на площадке (например, до 10 СВБР-100)? Или ограничим разумным минимумом (1–6)?
4. **Есть ли ещё известные кейсы** (кроме Сахалина), где уже посчитали экономику? Это сразу усилит калибровку модели.
