# ВОСТОК-612. Подбор конфигурации АСММ для заданного города

Команда `city` получает профиль региона, список участков с городом, каталог реакторов и сценарии. Она перебирает сочетания участка, реактора и числа модулей, проверяет заданные ограничения, ранжирует варианты в каждом сценарии и возвращает лидеров по доле первых мест.

## Быстрый запуск

```sh
python3 -m pip install -r requirements.txt
python3 -m nuclear_dss city --city 'Учебный Северный' --out results/city_demo
python3 -m nuclear_dss city --city 'Учебный Восточный' --out results/city_abstain
python3 -m nuclear_dss city --city 'Учебный Северный' --imputation context-ridge --out results/city_context
python3 -m nuclear_dss city --city 'Учебный Северный' --imputation gpr --out results/city_gpr
python3 -m scripts.benchmark_site_imputation --manual-workbook 'КОНГРЕСС/Выбор места.xlsx'
python3 -m scripts.benchmark_city_ml --out results/city_ml
python3 -m pytest -q tests
```

Чтобы зафиксировать площадку, добавьте, например, `--site-id S1`. Без этого параметра участвуют все переданные площадки выбранного города. Оба города и их сценарии синтетические. Реакторный каталог и таблица исторических оценок входят в проект.

## Входы

| Параметр | Формат |
|---|---|
| `--region` | JSON с `region_id`, `name`, `demand_mw.min/max` для совместимости с региональным скринингом, `max_modules` и необязательным верхним пределом общей мощности. В городском режиме диапазон нагрузки для отбора формируется по сценариям выбранного города. `scenario_screen` задаёт нижний и верхний коэффициенты отношения установленной мощности к спросу. Параметр `scenario_analysis_years` задаёт общий расчётный горизонт эксплуатации, по умолчанию 40 лет. |
| `--sites` | CSV с `site_id,region_id,city,name,source_status,source_reference` и характеристиками из примера. `land_restriction=none` разрешает перейти к расчёту по исходным данным. Неизвестное ограничение останавливает подбор для площадки. Шесть оценок площадки от 1 до 5 можно передать в полях `deficit,oyat,logistics,industry,economy,geo_climate`. |
| `--reactors` | CSV с `reactor,P_el_MW,dims,footprint`. Используется каталог проекта, если путь не указан. |
| `--scenarios` | CSV со схемой `region_id,city,scenario_id,demand_mw,tariff_rub_per_kwh,cost_profile,capex_factor,opex_factor,w_cost,w_power_fit,w_site_rubric`. Сумма весов каждой строки равна единице. Коэффициенты затрат равны единице при отсутствии соответствующих столбцов. Каждая строка выбранного города вносит одинаковый вклад в итоговую частоту. |
| `--history` | Необязательная замена исторической таблицы с уникальным полем `site` и шестью заполненными оценками. Для совпадающей площадки укажите `historical_site` в CSV участков, особенно если её название изменилось. |
| `--cost-estimates` | Необязательный CSV со столбцами `site_id,reactor,modules,capex_bln,cash_opex_bln_year,source_reference`. Затраты относятся ко всей конфигурации. В этом режиме отсутствие оценки затрат выводится как `NEEDS_COST_DATA`. Без файла используются сценарные финансовые профили из существующего расчётного ядра. |

```sh
python3 -m nuclear_dss city --region inputs/region.json --city 'Название города' \
  --sites inputs/sites.csv --scenarios inputs/scenarios.csv \
  --cost-estimates inputs/costs.csv --out results/my_city
```

## Дополнительные признаки для ML

Режим `--imputation context-ridge` принимает дополнительные поля в таблицах участков и исторических оценок. В этих таблицах используются одинаковые названия столбцов.

| Блок | Поля |
|---|---|
| Регион и география | `admin_region`, `latitude`, `longitude`, `population` |
| Энергетика | `local_demand_min_mw`, `local_demand_max_mw`, `annual_electricity_gwh` |
| Инфраструктура | `grid_connection_distance_km`, `rail_distance_km`, `port_distance_km`, `transport_max_diameter_m` |
| Участок и климат | `available_land_m2`, `heating_degree_days_18c` |

Числовая историческая строка должна иметь `context_source_status=documented` и заполненное `context_source_reference`. Строки со статусом `illustrative` или `unknown` исключаются из обучения на дополнительных признаках. Числовой признак должен иметь хотя бы четыре значения и ненулевой разброс в обучающей выборке. Регион используется при наличии хотя бы двух примеров из этого региона. Масштаб числовых признаков и категории определяются заново в каждой обучающей выборке. Если для оцениваемой площадки подходящих признаков нет, применяется медиана. В `report.json` указаны переданные и использованные поля, а также число отложенных площадок, для которых признаки удалось применить.

В комплектной истории единственный дополнительный признак — административный регион, извлечённый из названий площадок в ручной таблице. Сценарные численные значения из демонстрации применяются на этапе городского расчёта. Подтверждённая отдельная историческая таблица нужна для проверки эффекта остальных признаков.

## Метод

1. Из входов выбираются пары площадок и сценариев указанного города в заданном регионе. Общий диапазон спроса городских сценариев используется для первичного отбора конфигураций.
2. В каждом сценарии проверяется допустимый диапазон мощности. Локальный или региональный транспортный предел можно включить в жёсткие сценарные фильтры параметрами `site_transport_hard_scenario_gate` и `transport_diameter_hard_scenario_gate`. При включённом региональном фильтре требуется число в `max_transport_diameter_m`. Расчёт использует каталожный габарит. Отдельный файл фиксирует инженерные исследования, в том числе по логистике, геологии и сейсмике.
3. Оценка варианта — взвешенная сумма трёх величин от 0 до 1. Блок экономики использует отношение `тариф / (тариф + LCOE)`. Соответствие мощности определяется как меньшее из `мощность / спрос` и `спрос / мощность`. Последняя величина равна среднему шести оценок площадки, линейно приведённому к шкале от 0 до 1. NPV выводится для анализа вместе с LCOE.
4. Если известна хотя бы одна мягкая оценка, по умолчанию пропуски заполняются исторической медианой. `--imputation bayesian-ridge` обучает модель для каждого пропуска, `blend` усредняет её прогноз и медиану, `auto` выбирает один из этих методов по MAE для конкретного набора пропусков, а `none` отключает восстановление. `context-ridge` использует оценки и дополнительные признаки. В `auto` ошибка выбранного метода оценивается во внешнем цикле leave-one-site-out. Для сценариев выбирается совместный вектор ошибок с одной отложенной площадки. Этот вектор общий для всех конфигураций площадки внутри сценария. Поток генератора задаётся по `seed` и идентификатору площадки. Жёсткие ограничения используют исходные поля.
5. В отчёте частота попадания в топ-k равна доле всех сценариев, в которых вариант прошёл фильтр и попал в первые k мест. Сценарии с пропусками, отклонёнными вариантами или пустым списком входят в знаменатель. Равные оценки делят место, например 1, 1, 3. В финальный список входят варианты с вычисленным рангом не менее чем в 80% сценариев. Этот исследовательский порог можно изменить через `--min-feasible`. Из списка выбираются все варианты с максимальной долей первых мест.

`--imputation gpr` восстанавливает отдельные мягкие оценки по остальным известным оценкам площадки. Используется гауссовский процесс с фиксированным ядром Matérn 3/2 и нормализацией признаков внутри обучающей выборки. Сценарные значения формируются по ошибкам на отложенных площадках, как и для Ridge. Метод `auto` сохраняет прежний набор кандидатов. Команда `train-expert` относится к отдельной задаче прогноза независимой итоговой оценки площадки.

Обучение использует исторические оценки отдельных критериев. Ошибка модели по скрытым баллам служит внутренней диагностикой. Частоты характеризуют поданные сценарии и применимы к предварительному сравнению. Подтверждение затрат и пригодности реального участка требует независимых данных и профильной инженерной оценки.

## Результаты проверок

Автоматические тесты охватывают границы отбора по городу, учёт пустых сценариев в знаменателе, повторяемость запуска, явный ввод затрат, обработку неизвестного жёсткого ограничения, исключение тестовой площадки из обучения и использование числового признака через команду `city`.

Для «Учебного Северного» проверены 234 сочетания на 3 площадках по 9 сценариям. В финальный список вошли 16 вариантов. ALFRED и OTRERA 300 по одному модулю на участке S1 получили по 3 первых места из 9. В топ-3 они вошли в 5 и 3 сценариях соответственно. Для «Учебного Восточного» список лидеров пуст из-за нерешённой проверки земельных ограничений.

В сравнении с ручной таблицей на 21 площадке медиана дала среднюю абсолютную ошибку **0,786 балла** при скрытии одного или двух критериев. У Bayesian Ridge ошибки составили 0,816 и 0,821 соответственно. При двух пропусках среднее смещение относительно ручного ранга снизилось с 2,375 до 2,305 места. `auto` дал 0,781 балла при одном пропуске и 0,821 при двух. Результаты относятся к внутреннему эксперименту на исторических баллах. Код проверяет все 6 одиночных и 15 парных масок, каждый раз исключая оцениваемую площадку из обучения.

При полных данных скрипт воспроизводит ручную сумму на всех 21 площадках. Большой Камень занимает первое место с 25 баллами из 30. Для четырёх реакторов из ручного финального сравнения скрипт отдельно воспроизводит отсев по мощности 50–150 МВт и каталожному диаметру до 4,5 м. Оба условия проходят СВБР-100 и OTRERA 300. Финальный ручной выбор СВБР-100 использовал дополнительные качественные критерии.

Городской эксперимент сравнивает пять режимов, включая GPR, на одинаковых скрытых оценках. Проверяются рассеянные и блочные пропуски, исключение площадки и исключение её региона целиком. Отдельный эксперимент сравнивает три правила выбора одного уточняющего запроса. Протокол, результаты, ограничения и CSV приведены в [отчёте](experiments/city_ml_2026/RESULTS.md).

## Выходы

- `ranking.csv` содержит конфигурации, статус, доли прохождения фильтров и топ-1/топ-3, среднюю потерю балла в сценариях с вычисленным рангом.
- `scenario_outcomes.csv` содержит ранг, показатели экономики и причину пропуска отдельного сочетания в каждом сценарии.
- `constraint_audit.csv` содержит результаты проверок и основания для каждого ограничения.
- `study_requests.csv` перечисляет необходимые изыскания по вариантам и площадкам.
- `report.json` сохраняет результаты, диагностику заполнения оценок, параметры и контрольные суммы входов.
