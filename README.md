# ВОСТОК-612 — исследовательский ML-пайплайн и сценарная экономика

Актуальный вход для выбора конфигурации АСММ по региону и городу — команда `city`. Формат данных, быстрый запуск и описание дополнительных признаков приведены в [README_CITY.md](README_CITY.md). [Отчёт об экспериментах](experiments/city_ml_2026/RESULTS.md) содержит сравнение с ручным анализом, проверку переноса на новый регион и эксперимент с уточняющими запросами. Снимки статей для архива находятся в [docs/articles](docs/articles).

**Воспроизводимый ML-пайплайн и расчётное ядро исследовательской системы поддержки решений** площадок и реакторов малой мощности. Включает проверку данных, правила отсечения, сценарную экономику, опциональную Gaussian Process Regression (GPR) на **независимых экспертных метках**, эвристический риск, Monte Carlo и настоящий Парето-фронт.

**Важно.** Это исследовательский демонстратор, а не обоснование размещения, ядерной/экологической безопасности, лицензирования, строительства или инвестиций. Пример спроса, тарифа, характеристик транспорта и геориска не подтверждён первичными источниками. Все кандидаты имеют статус `REQUIRES_VERIFICATION` независимо от места в рейтинге. Не используйте ранжирование для решений о реальных площадках без официальной инженерной и регуляторной оценки.


## Что поменялось после новых документов (15 ноября 2026)

Изучены `Тезисы AtomFuture.docx`, `КОНГРЕСС ОЩИЙ ДОКУМЕНТ.docx`, `Большой камень вся экономика.xlsx` и прежняя `research_article(1).md`.

1. **Смета:** добавлен профиль `bigstone_2026`, импорт сумм по строкам, исключение неденежной амортизации и тесты сверки. До изменения использовались сценарные якоря 93,5/6,75 млрд ₽.
2. **Доказательность:** новая смета подтверждает арифметику 77/5,18, но не рыночную реалистичность, контрактность и стоимость других технологий. Поле `cost_anchor_applicability` показывает, когда рассчитанный вариант переносит этот единичный кейс на другое сочетание. **В обычном демосценарии все 276 оставшихся вариантов используют такую экстраполяцию**: для Большого Камня условный спрос в CSV = 250 МВт, а документ — оценка одного блока 100 МВт. Поэтому даже положительный NPV в деморейтинге не является подтверждением выгодности.
3. **Сверка источников:** `source-audit` фиксирует число площадок 17 vs 21, девять критериев/25 из 27 vs шесть критериев/25 из 30, 60 vs 50 лет службы СВБР, 80–85% vs 90% КИУМ, 500–800 МВт регионального дефицита vs отсутствия проверенного локального спроса и неясное название порта «Корсаков» в смете Большого Камня.
4. **Новая модель:** добавлена процедура честного бенчмарка `compare-models` на подлинных независимых оценках: GPR, BayesianRidge, SVR, опционально **TabPFN-3.5** (сентябрь 2026). Данных для предметного запуска ML-бенчмарка всё ещё **нет**: имеющийся `expert_score` — сумма входных шести критериев. Тестовые синтетические сигналы не записываются в итоговые исследования.
5. **Эксперименты:** папка `experiments/` содержит результаты обновлённого и старого экономических профилей, 60-летнего what-if и таблицу чувствительности пилотного кейса. Эти результаты воспроизводимы, но не являются оценкой реального размещения атомного объекта.

Технические подробности, примечания к научной статье и ссылки на документацию модели находятся в `RESEARCH_UPDATE.md`.

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python -m nuclear_dss validate
python -m nuclear_dss source-audit
python -m nuclear_dss run --reactor СВБР-100 --samples 500 --seed 42 --out results
pytest -q
```

Результаты: `results/ranking.csv` (предварительное ранжирование и чувствительность к весам), `results/excluded.csv` (исключённые сочетания и точные причины), `results/report.json` (настройки, диагностика, предупреждение при отсутствии вариантов с положительным NPV, оговорки). Для проверки всего каталога: `python -m nuclear_dss run --reactor ALL --samples 100 --out results_all`.

**Внимание:** расчёт по `data/scenario_demo.csv` является иллюстративным. В сценарии условный спрос в МВт сопоставлен исходным порядковым баллам `deficit` по схеме `1→25; 2→50; 3→90; 4→160; 5→250`. Это **не измерение** и **не метод перевода** баллов в МВт. Условный тариф одинаков для всех площадок (15 ₽/кВт·ч); это **не действующий тариф**. Прочие незаполненные значения и сведения о площадках перенесены из непроверенных текстовых профилей прежнего прототипа, а не из геоизысканий. Для предметного анализа замените сценарий проверенными данными с документированным происхождением; `data_status=measured` ставьте только после проверки первичных источников и заполнения `source_reference` для каждой измеренной строки (программа проверяет наличие ссылки, но не подтверждает достоверность измерения).

## Данные

- `data/sites.csv`: 21 площадка, шесть оценок 1..5 и их арифметическая сумма `expert_score`. Не спутайте ordinal `deficit` с **измеренным спросом МВт**.
- `data/reactors.csv`: 26 наименований и табличные паспортные/проектные характеристики. Техническая зрелость, лицензируемость и реальная осуществимость НЕ верифицированы. Пропуски не заменяются вымышленными габаритами/площадью.
- `data/scenario_demo.csv`: 21 гипотетический сценарий спроса/выручки и вспомогательных факторов. Для реальных расчётов необходим независимый source-of-truth.
- `data/economics_bigstone_2026.json`: проверенная **арифметика** из новой сметы Большого Камня (не проверенная достоверность самой сметы) с ячейками-источниками. CAPEX = 77 млрд ₽, валовый OPEX = 5,18 млрд ₽/год, в том числе амортизация 1,28; денежный OPEX = 3,90. Источник — загруженная таблица «Большой камень вся экономика.xlsx».

Диагностика сообщает, что **21/21 `expert_score` = сумма шести входов**, т.е. пытаться «обучать» модель предсказывать этот столбец бессмысленно: метка искусственно создана из признаков. В режиме по умолчанию используется **точная арифметика без притворной ML-точности**.

## Независимые метки: включение настоящего ML

После **независимого** опроса нескольких экспертов можно создать отдельный CSV (желательно через встроенную процедуру сбора, см. ниже):

```csv
site,independent_expert_label
<название_из_sites.csv>,<оценка_0..30>
```

Нужно минимум восемь независимых оценок разных площадок; хотя бы часть оценок должна отличаться от исходной арифметической суммы, иначе обучение отказывается от производной метки. Эти оценки должны быть получены из внешней процедуры с известной шкалой, а не придуманы или скопированы из `expert_score`.

```bash
python -m nuclear_dss labels-template --experts 3 --out expert_ratings_blank.csv
# заполнить score, method, source_reference для каждого эксперта независимо
python -m nuclear_dss aggregate-labels --ratings expert_ratings_filled.csv --min-experts 3 --out independent_labels.csv
python -m nuclear_dss evaluate-expert --labels independent_labels.csv
python -m nuclear_dss train-expert --labels independent_labels.csv --out trained_expert
python -m nuclear_dss predict-expert --model trained_expert/expert_gp.joblib --out expert_predictions.csv
python -m nuclear_dss run --model trained_expert/expert_gp.joblib --reactor СВБР-100 --out results_gp
```

Используются `StandardScaler` + `GaussianProcessRegressor` с Matérn 3/2 и шумовым ядром (фиксированные гиперпараметры). Метрики: `leave-one-site-out MAE/RMSE` для GPR и baseline Ridge, среднего по обучению и арифметической суммы; дополнительно диагностические 90%-coverage и Gaussian NLL. Интервалы **не калиброваны**. Нормализация обучается **только на тренировочных fold**; `expert_score` **никогда не используется как вход GP**. При 8-21 метках оценки неопределённости GP нуждаются во внешней калибровке. Без независимых меток ML-блок сознательно не обучается.

## Как работает конвейер

1. **Data checks:** обязательные столбцы, уникальность объектов, положительные МВт и тарифы, range check 1..5, диагностика пропусков, меток и сценариев.
2. **Gate:** ограничения сценария 0.8×demand ≤ `n × P_el` ≤ 1.5×demand и демонстрационный порог P_el ≤ 350 МВт. Это инженерные **эвристики, не нормативы**. Сейсмика/вода/масса/охлаждение не считаются пройденными, если данных нет.
3. **Expert:** исходная арифметическая сумма 6..30; опционально GP на независимых экспертных метках. Поле `expert_std` - модельная σ, **не** неопределённость безопасности.
4. **Economics:** сценарные CAPEX/OPEX, дисконтированные денежные потоки, **ограничение продаваемой энергии спросом**, отдельные сроки строительства, NPV, LCOE, простой срок окупаемости и требуемый для NPV=0 тариф. По умолчанию использован новый оценочный якорь 77 млрд ₽ CAPEX + 3,90 млрд ₽/год **денежного** OPEX (валовые 5,18 млрд включают 1,28 млрд амортизации, которую нельзя дважды учитывать при CAPEX). В OPEX есть условные отчисления в фонд вывода 0,5 млрд ₽/год, но полноценная стоимость вывода из эксплуатации, финансирования, налогов и обращения с ОЯТ не верифицирована. На иных реакторах, площадках или числе модулей вся экономическая модель — **неподтверждённая экстраполяция** одного пилотного кейса, не инвестиционный прогноз.
5. **Monte Carlo:** одинаковые случайные шоки для всех сочетаний; треугольные сценарии CAPEX/OPEX/тарифа/спроса/доступности и задержки стройки. Отчёт содержит p05/p50/p95 по NPV **и LCOE**, CVaR05 и долю сценариев с NPV>0. Эта доля **не оценка реальной вероятности**.
6. **Ranking:** взвешенная агрегация `[NPV .45; expert .25; low-risk .20; fit-demand .10]`. NPV приводится к 0..1 по 5/95 перцентилям ВНУТРИ набора кандидатов; нельзя сопоставлять итоговые баллы между разными наборами.
7. **Weight sensitivity:** 100 фиксированных по seed вариаций весов из Dirichlet, сводка `weight_sensitivity_top5_share`, `rank_median` и `rank_p95`. Это проверка условной устойчивости к приоритетам, не «вероятность лучшего проекта».
8. **Pareto:** строгий недоминируемый фронт четырёх критериев NPV↑ / риск↓ / эксперт↑ / соответствие спросу↑. Риск - субъективная **эвристика условий и пропусков**, не риск аварии.

## Полезные параметры CLI

```bash
python -m nuclear_dss run --help
```

- `--scenario path`: свой CSV со столбцами `site,demand_mw,tariff_rub_per_kwh,data_status` (при `measured` обязательно `source_reference`) и (желательно) `seismic_balls,water_available,port_type,permafrost,has_rail`.
- `--reactor ALL`: полный каталог, иначе поиск подстроки в названии.
- `--samples 1000 --seed 42`: MC-итерации и воспроизводимость.
- `--max-modules 3 --max-reactor-mw 350`: явные сценарные ограничения.
- `--labels path`: независимые целевые экспертные оценки 0..30, режим обучения на лету; вместо этого можно использовать `--model trained_expert/expert_gp.joblib`.
- `--rank-stability-samples 100`: сколько вариаций весов для анализа чувствительности.
- `--cost-profile bigstone_2026` (по умолчанию): новая смета Большого Камня; `--cost-profile legacy_2026`: исходные 93,5 / 6,75 млрд ₽, максимум 40 лет, для воспроизводимости старой версии.
- `--operation-life-override 60`: только отдельный what-if; для СВБР-100 в каталоге **50 лет**, а в тезисах 60 лет.
- `source-audit`: автоматическая сверка арифметики Excel-выгрузки и перечень междокументных противоречий.
- `compare-models --labels independent_labels.csv --out model_benchmark`: независимый LOO-бенчмарк GPR, BayesianRidge, SVR. `--tabpfn` добавляет **опциональный** TabPFN-3.5; требуется `pip install tabpfn`, принятие отдельной лицензии и доступ к чекпойнту, код проекта его не скачивает сам.
- `PYTHONPATH=. python scripts/reference_case_whatif.py`: воспроизводимая сравнительная таблица двух профилей стоимости, сроков 50/60 лет и тарифов/КИУМ; спрос в демонстрации задан как **неподтверждённый**.
- `python scripts/import_economics_workbook.py путь/к/исходной.xlsx`: повторный импорт сметы через библиотеку `artifact_tool`, если исходный XLSX доступен.
- `labels-template --experts 3` и `aggregate-labels --ratings ...`: создание пустого бланка и агрегация реальных документированных оценок; `train-expert --labels ... --out ...`: пакет обученной GP-модели, out-of-fold прогнозов, метрик и JSON model card.
- `predict-expert --model ...`: оценивание новых/имеющихся площадок доверенным обученным артефактом. `joblib` использует pickle, поэтому **никогда не загружайте непроверенные внешние модели**.

## Недостаточно для научного или промышленного подтверждения

Обязательны независимые метки экспертов, реальные нагрузки/профили потребления и оптовые/контрактные тарифы, проверенные CAPEX/OPEX нескольких реализованных кейсов, оценка доступности и правового статуса технологии, логистическая схема, разрешённый землепользовательский контур, вода/охлаждение, демография, мониторинг внешних опасностей, аварийное планирование, обоснование обращения с ОЯТ/РАО, согласование с регулятором, sensitivity/uncertainty calibration. Самодельные эвристики нельзя трактовать как заключение по этим вопросам.

См. `RESEARCH_UPDATE.md` и исходную статью `research_article(1).md` (поставлялась отдельно). Старые численные выводы статьи относятся к профилю `legacy_2026`; они **не автоматически переносятся** на новый профиль. Неоднозначности новых документов не исправлялись задним числом.

## Валидационный контракт и границы ML

- Для GPR, которая прогнозирует независимый итоговый экспертный балл, нужны новые метки. Городская команда `city --imputation gpr` обучает отдельную модель для восстановления пропущенных критериев на имеющейся исторической таблице.
- Если метки есть, `train-expert` создаёт `expert_gp.joblib`, `metrics.json`, `cv_predictions.csv` и `model_card.json`. В `model_card.json` записаны схема шести признаков, SHA-256 обучающих записей и диагностические метрики LOO.
- Все метрики вычисляются из предсказаний для объектов, не входивших в соответствующий обучающий fold. Кернел и коэффициент регуляризации фиксированы заранее, а не подобраны на этих же метриках.
- `data_status=illustrative` у всех записей демонстрационного сценария. Не выдавайте ни рейтинг, ни метрики Monte Carlo, ни балл `risk_proxy` за доказательство безопасности или фактическую коммерческую оценку.
- При `NO_POSITIVE_NPV_UNDER_ASSUMPTIONS` относительное первое место **не означает**, что хотя бы одна альтернатива экономически выгодна по принятым предпосылкам.
- Функциональный продукт целиком описан в отдельной научной статье. В этом ZIP находится только воспроизводимое ML/расчётное ядро, а не веб-приложение.

## Подбор конфигурации по региону и городу

Новый пайплайн `python -m nuclear_dss city` отбирает площадки заданного города, рассчитывает сценарные фильтры и доли попадания в топ-1 и топ-3, обучает модель для пропущенных мягких оценок. Варианты с одинаковой долей первых мест выводятся вместе. Форматы входов, запуск и результаты проверок описаны в [README_CITY.md](README_CITY.md).
